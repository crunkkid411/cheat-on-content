# Migration: schema_version 1.3 → 1.4

> **Type**: MINOR **but BREAKING for blind channel integrity** — state fields are unchanged, but `rubric_notes.md` must be split. **Until a legacy user runs migrate, the blind sub-agent still leaks actual performance**.

---

## WHAT changed

### File layer (**the core**)

| Before | After |
|---|---|
| `rubric_notes.md` accumulated all bump memos at the top (including video names + actual performance + derived evidence) | `rubric_notes.md` contains only generic language (formula / dimension definitions / bucket boundaries / pointers) and **never** actual performance |
| —— | `rubric-memo.md` (**new**) accumulates the full text of all bump memos (including video names + actual performance + derived evidence) |

### State fields

No additions / removals / renames. Only `schema_version` is bumped to mark that this "file-layer migration" must run.

### Channel B hard refusal list

`cheat-score-blind/SKILL.md` gains the `rubric-memo.md` path + refusal_code `blocked_rubric_memo`.

---

## WHY

PR #11 introduced the blind-scoring sub-agent (channel B) with a promise that it can only read `scripts/<id>.md` + `rubric_notes.md`. But when cheat-bump Phase 5 was implemented, it wrote upgrade memos (including evidence data tables + derived evidence + real video names + actual performance) into rubric_notes.md — the sub-agent read actual-performance data through the whitelist that it should never have seen, turning blind scoring into "post-hoc rationalization after seeing the actual performance".

Reproduced in practice (PR #11 testing):

```
contamination_note: rubric_notes.md v0→v1 bump memo contains an entry with the same name as this script, "It Made Me Post" at 380k actual
contamination_note: rubric_notes.md derived-evidence section contains this script's name + 137k actual; the CC anchor was pre-calibrated
→ refusal: "non_blind_warning"
→ all dimensions confidence: medium
```

Fix: split the file. `rubric_notes.md` holds strictly generic rules (blind whitelist), and bump history archives settle into `rubric-memo.md` (hard-forbidden for blind). See the "Blind channel leak guard" section in [shared-references/observation-lifecycle.md](../shared-references/observation-lifecycle.md).

---

## HOW (Claude steps for /cheat-migrate)

Execute in order. **Steps that are not idempotent must first check whether they already ran** — this migration rewrites content files, and a rerun may produce duplicate content.

### Step 1: Pre-flight check

1. Read `.cheat-state.json` → verify `schema_version == "1.3"`, otherwise error "the current state is not 1.3; this migration is not needed"
2. Check that `rubric_notes.md` exists; if not → error "cannot find rubric_notes.md. Has the project been initialized?"
3. Check **whether `rubric-memo.md` already exists**:
   - Exists → ask the user "rubric-memo.md already has content; skip the split and bump schema to 1.4? Reply yes to skip, no to abort the migration"
   - Does not exist → go to Step 2

### Step 2: Back up

```bash
cp rubric_notes.md rubric_notes.md.backup-$(date +%s)
```

Tell the user: "`rubric_notes.md` backed up — restore it if the split goes wrong".

### Step 3: Scan + extract the forbidden sections of `rubric_notes.md`

Read all of `rubric_notes.md`. Identify the following patterns:

| Pattern | Handling |
|---|---|
| A whole `## v.X → v.Y upgrade memo` section with subsections (trigger observation / evidence data / diagnosis / cross-model audit / known limitations) | **Extract the whole section** into rubric-memo.md and **delete it in place** |
| A derived-evidence section carrying video names + numbers (e.g. "Stop Expecting" 137k actual) | **Extract the whole item** into rubric-memo.md's "derived evidence" subsection; replace it in place with generic language ("high-abstraction-density sample → CC=1 → low reach") |
| Calibration-pool re-score table / ranking comparison table | **Extract the whole table** into the corresponding memo's "evidence data" subsection in rubric-memo.md; delete it in place (keep the formula quick-reference table — it contains no video names) |
| Cross-model audit references containing concrete video names + actual performance | Extract |
| Scattered `\d+w` / `\d+万` numbers (**exception: bucket boundaries** such as 5-30w / 30-100w stay) | Let Claude judge: a bucket boundary → keep; an actual-performance reference → extract |

### Step 4: Write `rubric-memo.md`

If the file does not exist → copy the empty skeleton from `cheat-on-content/templates/rubric-memo.template.md`.

Then append the memo sections extracted in Step 3 **in chronological order** (oldest first / newest last) to the end of the file. Wrap each memo section in the 6-component format of [templates/rubric-memo.template.md](../templates/rubric-memo.template.md); mark missing components as `(unknown from legacy migration)`.

### Step 5: Clean up `rubric_notes.md`

- Add to the top metadata block:
  ```markdown
  **Upgrade memos**: see [rubric-memo.md](rubric-memo.md)
  ```
- Where Step 3 extracted a memo section, leave a **short pointer**: "The v0→v1 upgrade memo has been migrated to rubric-memo.md; run `cat rubric-memo.md` to view it"
- Replace derived-evidence sections with generic language

### Step 6: Leak-guard self-check

Run against the cleaned `rubric_notes.md`:

```bash
grep -E '\d+\s*[wWmMkK万]|播放|实绩|实际' rubric_notes.md \
  | grep -v -E '^\s*\|[^|]*\|[^|]*\|.*[0-9]+\s*[wkM][^a-zA-Z]' \
  | grep -v -E '5-30w|30-100w|100-150w|>150w'
```

(the greps exclude obvious bucket-boundary numbers)

- No hit → pass
- Hit → report the remaining "actual-performance references" + have the user review / extract further by hand → continue to Step 7 or abort

### Step 7: Bump the schema + write the state back

1. Set `schema_version = "1.4"` in `.cheat-state.json`
2. **Atomic write**
3. Report: "✅ Migration to 1.4 complete. `rubric_notes.md` now contains only generic language ({N} lines), and `rubric-memo.md` contains {M} historical memo sections. Backup kept: rubric_notes.md.backup-{ts}."

## Manual fallback

Users who do not want to run `/cheat-migrate` can **split it by hand**:

1. Back up: `cp rubric_notes.md rubric_notes.md.backup`
2. Cut all `## v.X → v.Y upgrade memo` sections wholesale from `rubric_notes.md` into a **newly created** `rubric-memo.md` (preserve chronological order)
3. Cut the video names + actual performance from derived-evidence sections into rubric-memo.md, and replace them in place with generic language
4. Add the pointer `**Upgrade memos**: see [rubric-memo.md](rubric-memo.md)` to the top of `rubric_notes.md`
5. Hand-edit `schema_version` in `.cheat-state.json` to `"1.4"`

Or the **laziest** route: delete `rubric_notes.md` and re-init (losing all historical observations + bump memos), run `bash install.sh`, then say "initialize" — cheat-init recreates both empty files. Only suitable for early users whose calibration pool is still small (< 5 items).
