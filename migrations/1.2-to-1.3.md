# Migration: schema_version 1.2 → 1.3

> **Type**: MINOR (compatible; an old state falls back via `state.get(field, default)` and will not crash, but running the migration aligns fields with the schema doc)

---

## WHAT changed

### 2 new fields in the state file

| Field | Type | Default | Meaning |
|---|---|---|---|
| `last_prediction_self_scored` | bool | `false` | Whether the last `/cheat-predict` used `--skip-blind` or chose b at Phase 2.5 (trusting the main Claude's self-estimate instead of the sub-agent's blind score) |
| `last_self_scored_at` | string / null | `null` | ISO 8601 timestamp of the most recent `last_prediction_self_scored=true`; cleared back to null the next time the sub-agent is used |

### New concepts (not in the state; in the prediction file header)

Introduces two header fields, **`BlindScored By`** + **`BlindScore Disagreement`** — see component 1 in [shared-references/prediction-anatomy.md](../shared-references/prediction-anatomy.md).

Older prediction files lack these two fields — **backfilling is not mandatory**; cheat-retro applies a graceful default when reading.

---

## WHY

v1.3 introduces the [skills/cheat-score-blind](../skills/cheat-score-blind/SKILL.md) sub-agent as channel B — the Task tool isolates the scoring action so the sub-agent sees only the script + rubric_notes.md, avoiding contamination of the main conversation by actual performance / retros / user attitude.

`/cheat-predict` Phase 2 uses the sub-agent by default; `--skip-blind` is the escape hatch. Once the escape hatch is used, a tracking trail must be left — that is why `last_prediction_self_scored` exists.

`/cheat-bump` Phase 2 **mandatorily** uses the sub-agent and accepts no fallback; so bump never sets `last_prediction_self_scored=true`.

---

## HOW (Claude steps for /cheat-migrate)

In order:

1. Read `.cheat-state.json` → parse the JSON
2. Verify `schema_version == "1.2"`, otherwise error "the current state is not 1.2; this migration is not needed"
3. Check the `last_prediction_self_scored` field:
   - Missing → default `false`
   - Already present (rare; the user hand-edited it) → keep the existing value
4. Check the `last_self_scored_at` field:
   - Missing → default `null`
   - Already present → keep the existing value
5. Set `schema_version = "1.3"`
6. **Atomic write**: write to `.cheat-state.json.tmp` → rename
7. Report: "✅ Migration to 1.3 complete. Added 2 fields, no fields removed."

**No backfill of old prediction files is needed** — when the `BlindScored By` field is missing it is treated as `unknown` (cheat-retro applies a graceful default while reading). If the user wants to mark "these old predictions were all inline-scored in the v1.2 era", they can manually add `BlindScored By: legacy-inline` to the file header — but **the migration does not do this automatically**, to avoid touching existing prediction files and tripping the immutability hook.

---

## Manual fallback

Users who do not want to run `/cheat-migrate` can **leave the state completely alone** — every skill falls back via `state.get(field, default)`, and new fields automatically use their defaults. But the `schema_version` field will keep showing `"1.2"`, and the SessionStart hook will keep emitting the mismatch warning.

If you want to clear the warning without running the skill, hand-edit:

```diff
 {
-  "schema_version": "1.2",
+  "schema_version": "1.3",
+  "last_prediction_self_scored": false,
+  "last_self_scored_at": null,
   ...
 }
```

The next `/cheat-predict` run through the sub-agent naturally touches both fields (writing them as false / null), so the hand edit is effectively optional.

---

## Acceptance

After the migration completes:
- `jq '.schema_version' .cheat-state.json` → `"1.3"`
- `jq '.last_prediction_self_scored' .cheat-state.json` → `false` (or the preserved old value)
- `jq '.last_self_scored_at' .cheat-state.json` → `null` (same as above)
- Run `bash hooks/session-start.sh` → the schema mismatch warning no longer appears
