# Migration: schema_version 1.1 → 1.2

> **Type**: MINOR (compatible; an old state falls back via `state.get(field, default)` and will not crash, but running the migration aligns shoots[] fields with the schema doc)

---

## WHAT changed

### 5 new fields on `shoots[]` items

| Field | Type | Default | Meaning |
|---|---|---|---|
| `scripts_path` | string | derived from the `prediction_file` path | pre-shoot draft path |
| `script_consistency` | enum | `"consistent"` | `"consistent"` / `"modified"` / `"lost"` — whether the script changed at shoot time |
| `script_diff_pct` | int / null | `null` | percentage of changed content 0-100; null if an old shoot never computed it |
| `v2_prediction_written` | bool | `false` | whether the prediction file already contains a `## Prediction v2` section (legacy `## 预测 v2` is also recognized) |
| `script_hash_at_shoot` | string / null | `null` | first 12 chars of the sha256 of `videos/<id>/script.md` |

### New concept (not in the state file; in the prediction file header)

The `Prediction Basis` field: `pre_shoot` (v1 default) / `post_shoot_pre_publish` (v2)

---

## WHY

v1.2 introduced "post-shoot script change triggers v2 prediction re-judgment" — cheat-shoot calls `/cheat-predict — mode: v2` when it detects a script diff ≥30%, appending a `## Prediction v2` section to the original prediction file.

So cheat-retro knows "which prediction enters the calibration calculation", shoots[] items must record whether a v2 exists and how strong the diff was (used during rubric upgrades to analyze "the user's revision patterns").

---

## HOW (Claude steps for /cheat-migrate)

In order:

1. Read `.cheat-state.json` → parse the JSON
2. Verify `schema_version == "1.1"`, otherwise error "the current state is not 1.1; this migration is not needed"
3. For each item in the `state["shoots"]` list:
   - If `scripts_path` is missing → derive from `prediction_file` (replace `predictions/` with `scripts/`)
   - If `script_consistency` is missing → default `"consistent"`
   - If `script_diff_pct` is missing → default `null`
   - If `v2_prediction_written` is missing → **scan the matching prediction file**:
     - `grep -qE '^## (Prediction v2|预测 v2)' <prediction_file>` → if matched write `true`, otherwise `false`
   - If `script_hash_at_shoot` is missing → default `null`
4. Set `schema_version = "1.2"`
5. **Atomic write**: write to `.cheat-state.json.tmp` → rename
6. Report: "✅ Migration to 1.2 complete. Processed N shoots[] items."

---

## Manual fallback

Users who do not want to run `/cheat-migrate` can **leave the state completely alone** — every skill falls back via `state.get(field, default)`, and new fields automatically use their defaults. But the `schema_version` field will keep showing `"1.1"`, and the SessionStart hook will keep emitting the mismatch warning.

If you want to clear the warning without running the skill, hand-edit:

```diff
 {
-  "schema_version": "1.1",
+  "schema_version": "1.2",
   ...
 }
```

The fields in shoots[] will be filled in as needed the next time cheat-shoot / cheat-publish runs.
