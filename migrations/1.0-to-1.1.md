# Migration: schema_version 1.0 → 1.1

> **Type**: MINOR (compatible; an old state read with defaults will not crash, but running the migration aligns field semantics)
>
> **Status**: This is v1's first formal migration — mainly a template and example. The vast majority of early users came straight out of init at 1.1 and need no migration.

---

## WHAT changed

### Removed fields

| Field | Old value | Why removed |
|---|---|---|
| `mode` | "cold-start" / "calibration" binary | Replaced by the `calibration_samples` integer — a hard switch was a designer's guess; a continuous integer is more accurate |
| `prediction_complexity` | "cold-start-simple" / "complete" | All predictions use the unified 7-component structure, and confidence derives from calibration_samples |
| `bucket_scheme` | "ratio" / "absolute" / "absolute_with_ratio" / "percentile" | Bucket boundaries are now derived by a single algorithm (with `baseline_plays` → multiple; without → platform default) |

### Added fields

| Field | Default | Writer |
|---|---|---|
| `typical_duration_seconds` | 240 | cheat-init Q1.5 derivation |
| `target_publish_cadence_days` | null (flexible cadence) | cheat-init Q1.6 derivation |
| `rubric_form_mismatch` | false | cheat-init (true when content_form ≠ opinion-video) |
| `benchmark_status` | "none" | cheat-init Phase 2.5 |
| `benchmark_name` | null | cheat-learn-from |
| `benchmark_sample_count` | 0 | cheat-learn-from |
| `baseline_plays` | null | cheat-init / cheat-retro |
| `enabled_perf_adapters` | `[]` | cheat-init |
| `last_published_file` | null | cheat-publish |
| `last_retro_at` | null | cheat-retro |
| `pending_retros` | `[]` | cheat-publish / cheat-retro |
| `shoots` | `[]` | cheat-shoot / cheat-publish |

---

## WHY

v1.0's `mode` was a discrete binary, forcing a choice between "the first 5 pieces are cold-start vs later calibration". Real channels are a **continuous spectrum** — there is no qualitative change between piece 4 and piece 6. Using an integer `calibration_samples` with a derivation table (see the confidence derivation table in [shared-references/state-management.md](../shared-references/state-management.md)) preserves the signal while removing the fake breakpoint.

Similarly, `bucket_scheme` forced the user to decide "how buckets are split", but the user had no data to decide with — letting the algorithm derive it from baseline_plays is the sensible approach.

## HOW (Claude steps for /cheat-migrate)

In order:

1. Read `.cheat-state.json` → parse the JSON
2. Verify `schema_version == "1.0"`, otherwise error "the current state is not 1.0; this migration is not needed"
3. Derive the new field values:
   - `typical_duration_seconds`: ask the user "how many seconds is your typical video?" (default 240)
   - `target_publish_cadence_days`: ask "target publishing frequency (1 = daily / 2 = every other day / 7 = weekly / null = flexible)" (default null)
   - `rubric_form_mismatch`: check whether content_form ≠ "opinion-video" (the v1.0 field is retained) → if so, true
   - `benchmark_status`: default "none"
   - `benchmark_name`: null
   - `benchmark_sample_count`: 0
   - `baseline_plays`: scan `predictions/` for reconstructed predictions containing actual performance → take the median play count; if none → null
   - `enabled_perf_adapters`: `[]`
   - `last_published_file`: null (cannot be reverse-derived from 1.0 fields)
   - `last_retro_at`: null (same as above)
   - `pending_retros`: scan `predictions/` for files with `published_at` but no `## Retrospective` (legacy `## 复盘` also accepted) → the list
   - `shoots`: scan `videos/` for folders with script.md whose matching prediction has no `published_at` → construct shoot entries
4. Remove fields: `mode`, `prediction_complexity`, `bucket_scheme`
5. Set `schema_version = "1.1"`
6. **Atomic write**: write to `.cheat-state.json.tmp` → rename
7. Report: "✅ Migration to 1.1 complete. Added N fields, removed 3 fields."

## Manual fallback

Users who do not want to run `/cheat-migrate` can hand-edit `.cheat-state.json`:

```diff
 {
   "schema_version": "1.0",
+  "schema_version": "1.1",
-  "mode": "cold-start",
-  "prediction_complexity": "cold-start-simple",
-  "bucket_scheme": "ratio",
+  "typical_duration_seconds": 240,
+  "target_publish_cadence_days": null,
+  "rubric_form_mismatch": false,
+  "benchmark_status": "none",
+  "benchmark_name": null,
+  "benchmark_sample_count": 0,
+  "baseline_plays": null,
+  "enabled_perf_adapters": [],
+  "last_published_file": null,
+  "last_retro_at": null,
+  "pending_retros": [],
+  "shoots": [],
   ...
 }
```

> After hand-editing, run `/cheat-status` to verify the state file can be read normally by every skill.
