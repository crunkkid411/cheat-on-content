# Adapter: linkedin-session (LinkedIn single-post analytics crawler)

Automatically invoked by `/cheat-retro` when `state.data_collection=adapter` + `platform=linkedin`.

> **Origin**: architecture copied from `douyin-session` (Playwright persisted login session + reading the rendered DOM).
> Single-post analytics (impressions / reach / reactions / …) has been verified end-to-end on a real LinkedIn account.

---

## What this adapter does

The LinkedIn single-post analytics page (`/analytics/post-summary/`) is **visible only to the post's author**, and the data is
SSR/inlined into the page — there is no public API, no stable voyager XHR to intercept, and plain HTTP / requests
(including Claude's WebFetch) gets no data at all.

linkedin-session uses **Playwright + a persistent Chromium context** to simulate a real browser:

- You log in to LinkedIn once (getting the `li_at` cookie); the cookie is stored in **your content project root** under `.auth-linkedin/`
- Every later fetch reuses the cookie, with no need to log in again
- It navigates to the single-post analytics page → reads the rendered DOM text → parses by known label anchors (**no reverse engineering, no forged requests**)
- It captures 10 metrics per post: impressions / reach / reactions / comments / reposts / saves / sends / social engagement /
  profile visits from the post / new follows from the post, plus the post body

Output is written to **your content project's** `videos/<...>/report.md` (`cheat-retro` reads this file → writes a summary into the prediction's retrospective section).
Debug artifacts (DOM text dumps) are written to `.cheat-cache/linkedin-session-debug/`, so they do not litter the skill source directory.

## An honest maintenance note: LinkedIn randomly switches between Japanese / English

Within the same account and the same session, LinkedIn randomly switches between the **Japanese UI** and the **English UI**
(labels change from `Impressions` to `インプレッション数`). So `extract.py`'s `POST_METRICS`
**stores two aliases for every metric** and tries both when parsing. If your UI is in a third language, just add
the corresponding labels to `POST_METRICS` (the multilingual aliases are a list; adding one does not affect the existing ones).

## Installation (one-time)

```bash
# 1. Enter your content project root
cd ~/my-channel

# 2. Create a virtual environment (strongly recommended — Playwright + Chromium is several hundred MB; do not pollute system Python)
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate

# 3. Install Playwright
pip install -r "$ADAPTER/requirements.txt"

# 4. Install Chromium (required the first time)
playwright install chromium

# 5. Log in to LinkedIn for the first time
ADAPTER=$(find ~/cheat-on-content -name "linkedin-session" -type d 2>/dev/null | head -1)
python "$ADAPTER/crawler.py" login
# → a Chromium window opens; log in to LinkedIn
# → the window closes automatically after login; the cookie (li_at) is stored in the current directory/.auth-linkedin/
```

> Note: the adapter lives at `~/cheat-on-content/adapters/perf-data/linkedin-session` (the cloned source),
> not in `~/.claude/skills` (install.sh only copies skills, not adapters).

## Usage

cheat-retro calls it automatically; you do not need to run it by hand. Manual testing:

```bash
cd ~/my-channel
source .venv/bin/activate

# Fetch a specific post (either the activity_id or the full post link works)
python "$ADAPTER/review.py" video 7470493738918920193 <video_folder>/script.md

# Output goes to current-directory/videos/<date>_<activity_id>_<author>/report.md
```

run.sh is the wrapper cheat-retro calls:

```bash
bash run.sh <activity_id_or_url> <video_folder> [<script_path>]
```

## How to get the activity_id

LinkedIn post URL forms:

- `https://www.linkedin.com/feed/update/urn:li:activity:7470493738918920193/` → `activity_id = 7470493738918920193`
- Analytics page `https://www.linkedin.com/analytics/post-summary/urn:li:activity:7470493738918920193/` → same as above

The adapter extracts the activity_id automatically from a full link (it also accepts a bare id).
When cheat-publish registers a publish it stores the activity_id in the prediction header, and cheat-retro reads that field at startup.

## report.md output format

Generated by `renderer.py`, in the same shape as douyin-session. It contains:

- Post metadata (author, time since publish, link, fetch time)
- Data snapshot (impressions / reach / reactions / comments / reposts / saves / sends / social engagement /
  profile visits from the post / new follows from the post + derived ratios: reaction rate / comment rate / repost rate / social-engagement rate)
- Post body (when extracted from the analytics-page DOM)
- The original script (passed in by cheat-retro)
- Comments (**the LinkedIn single-post analytics page gives only the comment count, not comment text** — report.md notes this; paste top comments manually)

## Failure modes (highest to lowest probability)

| Symptom | Cause | Handling |
|---|---|---|
| `ensure_login` times out | Cookie expired or LinkedIn forces reauth | Rerun `python crawler.py login` |
| Fetch is redirected to the login page | `li_at` is invalid | Rerun `python crawler.py login` |
| `impressions` is None / metrics missing | LinkedIn changed the layout or switched to a third language | Check `.cheat-cache/linkedin-session-debug/post_<id>.txt` and add the new labels to `POST_METRICS` in `extract.py` |
| No analytics data visible | The post was **not published by you** (single-post analytics is author-only) | You can only fetch your own posts |
| Body not captured | The analytics-page DOM occasionally omits the full body | report.md notes it; add the body manually |
| Chromium crashes / hangs | Usually insufficient machine memory | Close other Chromium instances; reinstall with `playwright install chromium --force` |

**Key reality**: LinkedIn offers no public data API for individual creators; single-post analytics can only be read from the page under a logged-in session.
Both the layout and UI language can change — this adapter **needs continuous maintenance**, and the first step is always to compare the
`post_<id>.txt` in the debug directory against the labels.

## Stability level

★★ — Playwright + a login session can get data that plain HTTP cannot, but parsing depends on DOM text layout +
UI language (Japanese/English randomly), so it is slightly more fragile than adapters that use JSON APIs. Suggest a manual run once a month to verify health.

## Risk notes

- **Cold-start users should install with care**: Playwright + Chromium ~500MB; newcomers are easily discouraged
- **TOS risk**: using your own cookie to fetch your own backend data is personal use; do not abuse it, do not run it at high frequency
- **Do not commit `.auth-linkedin/` to git**: the cookie (`li_at`) is equivalent to your LinkedIn session credential;
  a leak = someone else can log in to your LinkedIn account
- `.cheat-cache/linkedin-session-debug/` should also not be committed (it contains page DOM text dumps that may include personal information)
