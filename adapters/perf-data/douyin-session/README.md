# Adapter: douyin-session (Douyin crawler)

Automatically invoked by `/cheat-retro` when `state.data_collection=adapter` + `platform=douyin`.

> **Origin**: copies `crawler.py` / `review.py` / `renderer.py` from the reference creator's project (private) — validated on 25+ videos on a Chinese-language opinion-video creator account.

---

## What this adapter does

The Douyin video page is **heavily JS-rendered + loads comments via XHR + aggressively anti-scraped** — approaches without a browser engine and a login session (e.g. Claude's WebFetch, Python requests) get no data at all.

douyin-session uses **Playwright + a persistent Chromium context** to simulate a real browser:
- Scan the QR code to log in to the Douyin creator center the first time; the cookie is stored in **your content project root** under `.auth/`
- Every later fetch reuses the cookie, with no need to log in again
- It intercepts the Douyin frontend's XHR responses and reads the data API's JSON directly (no HTML parsing)
- It captures 3 kinds of data: video list / detailed data (completion / follow-conversion rate) / comments

Output is written to **your content project's** `videos/<...>/report.md` (`cheat-retro` reads this file → writes a summary into the prediction's retrospective section).
Debug artifacts (URL dumps / screenshots) are written to `.cheat-cache/douyin-session-debug/`, so they do not litter the skill source directory.

## Installation (one-time)

```bash
# 1. Enter your content project root
cd ~/my-channel

# 2. Create a virtual environment (strongly recommended — Playwright + Chromium is several hundred MB; do not pollute system Python)
python3 -m venv .venv
source .venv/bin/activate

# 3. Install Playwright
pip install playwright>=1.44

# 4. Install Chromium (required the first time)
playwright install chromium

# 5. Scan the QR code to log in to the Douyin creator center the first time
ADAPTER=$(find ~/.claude/skills -name "douyin-session" -type d 2>/dev/null | head -1)
# If not found (the adapter may not be global), use the source path:
# ADAPTER="$HOME/Desktop/cheat-test/cheat-on-content/adapters/perf-data/douyin-session"
python "$ADAPTER/crawler.py" login
# → a Chromium window opens; scan the QR code to log in to the creator center
# → the window closes automatically after login; the cookie is stored in the current directory/.auth/
```

## Usage

cheat-retro calls it automatically; you do not need to run it by hand. But if you want to test manually:

```bash
cd ~/my-channel
source .venv/bin/activate

# List recent videos (check whether the login session has expired)
python "$ADAPTER/crawler.py" list

# Fetch a specific video
python "$ADAPTER/review.py" video <aweme_id> <video_folder>/script.md

# Output goes to current-directory/videos/<date>_<title>/report.md
```

## How to get the aweme_id

Douyin video URL forms:
- `https://www.douyin.com/video/7234567890123456789` → `aweme_id = 7234567890123456789` (directly in the URL path)
- `https://v.douyin.com/abc123` → short link that needs resolving (cheat-publish does this automatically)

When registering a publish, cheat-publish stores the aweme_id in the prediction header (if it can be resolved). cheat-retro reads that field directly at startup.

## report.md output format

Generated by `renderer.py`. It contains:
- Video metadata (title, publish time, duration)
- Data snapshot (plays, likes, comments, reposts, saves + derived ratios: like-to-play / comment-to-play / share-to-play)
- Completion rate / 3s retention (if it can be captured)
- Top 20 comments (sorted by like count, including comment text + like count)
- Comment keyword clustering (done automatically by the renderer, optional)

## Failure modes (highest to lowest probability)

| Symptom | Cause | Handling |
|---|---|---|
| `ensure_login` times out | Cookie expired or Douyin forces reauth | Rerun `python crawler.py login` |
| `_parse_video_list` returns empty | Douyin changed the API fields — a structural change | Check the URLs captured in `.debug/creator_urls.txt` and update the field fallbacks in crawler.py |
| `_parse_video_list` video list is incomplete | Pagination did not capture everything — slow network or anti-scraping triggered | Increase the `await asyncio.sleep(...)` duration in `crawler.py` |
| Chromium crashes / hangs | Usually insufficient machine memory | Close other Chromium processes; reinstall with `playwright install chromium --force` |
| Comment fetching is slow (>5min) | The comment page's XHR triggers many scrolls — slow network | Lower `max_pages` in `fetch_comments_creator`, or switch to a more stable network |

**Key reality**: Douyin's API structure changes every few months. This adapter **needs continuous maintenance** — if it suddenly fails one day, the first step is to check the latest crawler.py in the "video analysis" project to see whether a new version exists.

## Stability level

★★ — The Playwright approach withstands far stronger anti-scraping than plain HTTP, but is still affected by Douyin frontend redesigns. Suggest a manual `crawler.py list` once a month to verify health.

## Risk notes

- **Cold-start users should install with care**: Playwright + Chromium is large (~500MB); newcomers are easily discouraged
- **TOS risk**: using your own cookie to fetch your own backend data is personal use; do not abuse it
- **Do not commit .auth/ to git**: the cookie holds your session credentials; a leak = someone else can log in to your Douyin account
- `.cheat-cache/douyin-session-debug/` should also not be committed to git: it may contain debug screenshots and API URL dumps
